From an HTTP Message to FastAPI Function Arguments

The HTTP chapter separated method, URL, headers, and body. This chapter follows one request through FastAPI and shows exactly how each part becomes a typed Python value. The Pydantic chapter then explains the body model in depth.

1) The endpoint declares the contract

from typing import Annotated

from fastapi import FastAPI, Header, Query
from pydantic import BaseModel, Field

app = FastAPI()

class QueryReq(BaseModel):
    question: str = Field(min_length=1, max_length=2_000)

class QueryResponse(BaseModel):
    collection_id: str
    q: str
    top_k: int
    auth_header: str | None

@app.post(
    "/collections/{collection_id}/query",
    response_model=QueryResponse,
)
def query(
    collection_id: str,
    req: QueryReq,
    top_k: Annotated[int, Query(ge=1, le=50)] = 5,
    authorization: Annotated[str | None, Header()] = None,
) -> QueryResponse:
    return QueryResponse(
        collection_id=collection_id,
        q=req.question,
        top_k=top_k,
        auth_header=authorization,
    )

The route decorator and function signature together form the boundary contract. FastAPI inspects the signature once when the application starts and builds validation plus OpenAPI metadata from it.

2) A real HTTP request message (what the client sends)

POST /collections/policies/query?top_k=10 HTTP/1.1
Host: api.example.com
Authorization: Bearer abc.def.ghi
Content-Type: application/json
Accept: application/json

{"question": "What does my policy say about refunds?"}

There are five separate inputs here: method, path template, path parameter, query parameter, header, and JSON body. FastAPI does not merge them into one undifferentiated dictionary.

Visual: one request, several typed sources

3) How FastAPI maps that message into your function arguments

A) Method + path decide which function runs

  • Method = POST
  • Path = /query

So FastAPI matches @app.post("/collections/{collection_id}/query") and selects query(...). A GET request to the same path would not match this route.

B) The path segment becomes collection_id

The route template names one dynamic segment: {collection_id}. The actual URL supplies policies, so FastAPI sets:

collection_id = "policies"

If the annotation were collection_id: UUID or collection_id: int, FastAPI would validate and convert the segment before calling the function.

C) Query string becomes top_k

From the first line: ?top_k=10

  • FastAPI finds top_k="10" in the query string
  • Converts "10" → 10 because you typed it as int
  • Checks ge=1 and le=50
  • If it wasn’t provided, it would use the default 5
Result: top_k = 10

D) Header becomes authorization

From the headers: Authorization: Bearer abc.def.ghi

Because you wrote: authorization: str | None = Header(None)

FastAPI reads the Authorization header and sets:

authorization = "Bearer abc.def.ghi"

If the header was missing, it would be None.

E) JSON body becomes req

From the body:

{ "question": "What does my policy say about refunds?" }

Because req is a Pydantic model (QueryReq), FastAPI:

  1. parses the JSON into a dict
  2. validates it matches QueryReq (must have question: str)
  3. constructs a Python object:
req = QueryReq(question="What does my policy say about refunds?")

So inside your function:

  • req is not “the raw request”
  • req is a validated object built from the JSON body
  • you access fields like req.question

4) What FastAPI effectively calls (conceptually)

query(
    collection_id="policies",
    req=QueryReq(question="What does my policy say about refunds?"),
    top_k=10,
    authorization="Bearer abc.def.ghi",
)

This is a mental model, not literal generated source code. FastAPI also resolves dependencies, handles async/sync execution, and builds an HTTP response around the return value.

Summary: That’s the whole mapping: query params → normal args, headers → Header(...) args, JSON body → Pydantic model arg (req), and the method+path choose the endpoint.

from fastapi import Depends

def query(
    collection_id: str,
    req: QueryReq,
    identity: Identity = Depends(get_verified_identity),
    top_k: Annotated[int, Query(ge=1, le=50)] = 5,
) -> QueryResponse:
    ...

6) Invalid input stops before business logic

If top_k=abc, if top_k=1000, or if the JSON body omits question, FastAPI does not call query(). Validation produces a structured 422 Unprocessable Content response that identifies the source and field path.

{
  "detail": [
    {
      "type": "less_than_equal",
      "loc": ["query", "top_k"],
      "msg": "Input should be less than or equal to 50",
      "input": "1000"
    }
  ]
}

Malformed JSON is also a client-input error. Authentication failures should be 401; authenticated callers without permission should receive 403; a hidden or absent resource is commonly 404. Do not turn all client errors into 500.

7) The return value travels back through a response contract

response_model=QueryResponse validates and serializes the returned data. It also filters undeclared fields, which helps prevent internal values from leaking into the API response. FastAPI uses the request and response models to generate OpenAPI documentation.

HTTP/1.1 200 OK
Content-Type: application/json

{
  "collection_id": "policies",
  "q": "What does my policy say about refunds?",
  "top_k": 10,
  "auth_header": "Bearer abc.def.ghi"
}

PyTorch Foundations: Tensors, Autograd, Modules, and Training

A practical journey through modern deep learning with PyTorch—from first principles to real applications.

Deep learning has transformed how we work with data, from recognizing images and understanding language to powering recommendation engines and game-playing agents. This book is a practical journey through modern deep learning with PyTorch, designed to take you from beginner to advanced without requiring a heavy math background (though pointers to deeper theory are provided if you want them).

We start from the very beginning

We start from the very beginning: linear regression and the idea of a neuron as a simple nonlinear transformation of a linear model. From there, we build up to deep neural networks, then explore specialized architectures:

  • Convolutional Neural Networks (CNNs) for images and signals
  • Recurrent Neural Networks (RNNs) and LSTMs for sequences and time series
  • Best practices for time series forecasting, including what commonly goes wrong in stock prediction tutorials

Why PyTorch

Along the way, you’ll see how PyTorch’s automatic differentiation and rich set of prebuilt layers let you focus on ideas and experiments instead of manually deriving and coding gradients. PyTorch became popular partly because its eager, Python-first execution model was easier to inspect than the static-graph-first workflows used by Theano and early TensorFlow. Modern TensorFlow also supports eager execution; both frameworks remain capable, while this book uses PyTorch for one consistent implementation path.

Practical applications

The second half of the book focuses on applications that matter in practice:

  • Natural Language Processing (NLP) and text classification
  • Embeddings for words and other categorical data
  • Recommender systems as used by companies like Amazon, Facebook, and Google
  • Transfer learning with pretrained models, allowing you to leverage massive datasets like ImageNet
  • Generative Adversarial Networks (GANs) for realistic image generation
  • Reinforcement Learning (RL) for sequential decision-making and control

Tensors: arrays with shape, dtype, and device

A tensor is a multidimensional numeric array. A scalar has no axes, a vector has one, a matrix has two, and a batch of color images often has four: [batch, channels, height, width].

import torch

scalar = torch.tensor(3.0)                       # shape: []
vector = torch.tensor([1.0, 2.0, 3.0])          # shape: [3]
matrix = torch.tensor([[1.0, 2.0], [3.0, 4.0]]) # shape: [2, 2]

print(matrix.shape)  # torch.Size([2, 2])
print(matrix.dtype)  # usually torch.float32 here
print(matrix.device) # cpu, unless moved to an accelerator

Shape describes axis lengths. Dtype describes numeric representation, such as float32 or int64. Device says where the storage and operation live, such as CPU, CUDA GPU, or Apple MPS. Tensors used in one operation must have compatible shapes, dtypes, and devices.

device = (
    "cuda" if torch.cuda.is_available()
    else "mps" if torch.backends.mps.is_available()
    else "cpu"
)

x = torch.randn(32, 10, device=device)  # 32 examples, 10 features each

Autograd: gradients from a recorded computation

Training asks: “How should each parameter change to reduce the loss?” PyTorch records operations involving tensors that require gradients. Calling backward() applies the chain rule backward through that computation graph.

w = torch.tensor(2.0, requires_grad=True)
x = torch.tensor(3.0)
y = w * x ** 2

y.backward()
print(w.grad)  # 9.0 because dy/dw = x^2

The graph is a record of operations for this forward pass, not a drawing you have to create manually. A new graph is normally built on the next pass. Gradients accumulate in .grad, which is why training loops clear them before the next backward pass.

Modules and parameters: a model is a callable object

nn.Module is the base class for trainable PyTorch components. It registers nested modules and parameters so the optimizer, device movement, saving, and training/evaluation modes work recursively.

from torch import nn

class LinearRegressor(nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = nn.Linear(in_features=1, out_features=1)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.linear(x)

model = LinearRegressor()
prediction = model(torch.tensor([[2.0]]))  # call model(...), not forward(...)

The learnable weight and bias are nn.Parameter objects. They are tensors with gradient tracking that were registered because self.linear is a child module.

The smallest complete training loop

This example learns the relationship y = 2x + 1. Later chapters change the data, model, and loss, but keep this loop structure.

import torch
from torch import nn

x = torch.tensor([[0.0], [1.0], [2.0], [3.0]])
y = torch.tensor([[1.0], [3.0], [5.0], [7.0]])

model = nn.Linear(1, 1)
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.05)

for step in range(500):
    model.train()

    prediction = model(x)           # 1) forward pass
    loss = loss_fn(prediction, y)   # 2) measure error

    optimizer.zero_grad()           # 3) clear old gradients
    loss.backward()                 # 4) compute new gradients
    optimizer.step()                # 5) update weight and bias

model.eval()
with torch.no_grad():
    print(model(torch.tensor([[4.0]])))  # close to 9

model.train() and model.eval() control layers whose behavior differs by mode, such as dropout and batch normalization. torch.no_grad() disables gradient recording for this evaluation block, reducing memory and work. It does not replace eval(); the two controls solve different problems.

The first debugging contract: inspect shape, dtype, device, and range

Before changing an architecture, print the boundary facts. Many apparent “model problems” are tensor contract problems:

print("x:", x.shape, x.dtype, x.device)
print("y:", y.shape, y.dtype, y.device)
print("prediction:", prediction.shape)
print("finite:", torch.isfinite(loss).item())
  • Regression predictions and targets usually need matching floating-point shapes.
  • Class indices for CrossEntropyLoss are normally torch.long.
  • Do not mix CPU inputs with a GPU model.
  • Do not silently broadcast incompatible target and prediction shapes.
  • Check for NaN or infinity before tuning hyperparameters.

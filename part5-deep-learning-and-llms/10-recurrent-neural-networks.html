Sequence models

Recurrent Neural Networks (RNNs): from sequence memory to GRU/LSTM and translation

A practical, code-oriented tutorial on why RNNs exist, what goes in and comes out at each time step, how a basic Elman unit computes hidden state, how GRU/LSTM gates improve memory, and how recurrent weight sharing keeps sequence models compact.

Big idea: An RNN processes a sequence by applying the same small neural “cell” at every time step. The cell carries a hidden state forward, so the output at time \(t\) can depend on both the current input \(x_t\) and the memory of earlier inputs \(h_{t-1}\).

1) Why not just flatten sequence data into a giant vector?

Sequence data is data where order matters: a time series, an audio waveform, a sentence, a video, or a stream of sensor readings. You can flatten a sequence \(X \in \mathbb{R}^{T \times D}\) into a single vector of length \(T\cdot D\) and feed it to a regular MLP. It works mechanically, but it’s usually a bad tradeoff:

  • Parameter explosion: dense layers connect “everything to everything”, so weights scale with \((T\cdot D)\).
  • Ignores sequential structure: treating time steps as just “features” discards the idea of incremental processing.
  • Hard to generalize across time: you’re not explicitly reusing patterns across positions in the sequence.
RNNs exploit the structure: the same computation repeats at every time step, just like CNN filters repeat across image locations.

Where RNNs show up

RNNs are useful whenever the meaning of the current item depends on what came before it. Modern Transformers dominate large-scale language modeling, but the RNN mental model is still important because it explains sequence memory, hidden state, autoregressive decoding, and the historical path into attention.

Problem family Why sequence memory matters Typical output shape
Language modeling Words depend on earlier words and phrase context. Next-token distribution at each time step.
Speech recognition Audio frames only make sense as an ordered waveform. Characters, word pieces, or phoneme labels over time.
Machine translation The target sentence depends on source order, grammar, and context. A generated output sequence.
Stock or demand forecasting Recent and older time steps can shape the next value. One future value, a horizon of values, or a class label.
Music generation Melody, rhythm, and harmony are sequential patterns. Next note, chord, token, or audio event.
Video and sensor streams Events unfold frame by frame or reading by reading. Per-step labels, anomaly scores, or a final classification.

2) The simplest RNN unit (Elman unit): equations and intuition

At each time step \(t\), the RNN consumes an input vector \(x_t \in \mathbb{R}^{D}\) and updates a hidden state \(h_t \in \mathbb{R}^{M}\). Then it optionally produces an output \(\hat{y}_t\).

Core equations

A standard “vanilla” RNN does:

\[ h_t = \phi(W_{xh}x_t + W_{hh}h_{t-1} + b_h) \] \[ \hat{y}_t = \psi(W_{ho}h_t + b_o) \]

Where:

  • \(W_{xh}\in\mathbb{R}^{M\times D}\): input → hidden weights
  • \(W_{hh}\in\mathbb{R}^{M\times M}\): hidden → hidden (recurrent) weights
  • \(W_{ho}\in\mathbb{R}^{O\times M}\): hidden → output weights
  • \(\phi\): hidden activation (often \(\tanh\) or ReLU); \(\psi\): output activation depends on task
  • \(h_0\): initial hidden state (often zeros; sometimes learned)

“Single unit is used”: what that really means

When people say “the same unit is used at each time step”, they mean:

  • You do not have a different \(W_{xh}\) for each \(t\).
  • You do not have a different \(W_{hh}\) for each \(t\).
  • You reuse the same weights and biases at every step: that’s parameter sharing through time.

The only thing that changes over time is the data (\(x_t\)) and the state (\(h_{t-1}\to h_t\)). This is exactly why RNNs can have far fewer parameters than a flattened dense design.

Cost nuance: the parameter count does not grow with \(T\), but the computation still runs once per time step, and training stores intermediate states for backpropagation through time. Long sequences can still be expensive.

3) Many-to-one vs many-to-many: why you might “ignore” most outputs

You can compute \(\hat{y}_t\) at every step, but whether you use them depends on the task:

  • Many-to-one: sentiment of a sentence → use only \(\hat{y}_T\)
  • Many-to-many: label each time step (e.g., tagging) → use all \(\hat{y}_t\)
  • Seq2seq (translation): outputs are also a sequence → you need stepwise predictions

Compact RNN summary

Feature Meaning
Input type Ordered data such as text, speech, time series, video frames, event streams, or sensor readings.
Core mechanism Reuse one learned cell through time while carrying hidden state forward.

4) Practical seq2seq example: translating “my name is dinesh”

A useful way to understand RNN inputs and outputs is to walk through a tiny machine-translation problem: translate “my name is dinesh” into “mon nom est dinesh”. A classic RNN translation system uses an encoder RNN to read the source sentence and a decoder RNN to generate the target sentence. The French target is a literal teaching example; an idiomatic translation might be “je m’appelle Dinesh”, but the literal four-token target makes the step-by-step alignment easier to see.

What the model sees: not raw text. Text is tokenized into IDs, IDs are looked up in an embedding table, and the RNN receives one dense vector per time step.

Step A: text becomes tokens, token IDs, then embeddings

Stage Example Shape / meaning
Source tokens ["my", "name", "is", "dinesh", "<EOS>"] A finite sequence ending with an explicit end-of-sentence marker.
Token IDs [17, 241, 9, 5021, 2] Integer vocabulary indices. The actual numbers are arbitrary.
Embeddings [0.12, -0.33, 0.45, ...] for each token If embedding size is \(D=300\), each time step gives the RNN one vector in \(\mathbb{R}^{300}\).
Padded batch ["my", "name", "is", "dinesh", "<EOS>", "<PAD>", ...] Padding makes examples in a batch the same length. Padding positions are masked or ignored; they are not extra meaning. 
import torch
import torch.nn as nn

src_tokens = ["my", "name", "is", "dinesh", "<EOS>", "<PAD>", "<PAD>", "<PAD>", "<PAD>", "<PAD>"]
src_ids = torch.tensor([[17, 241, 9, 5021, 2, 0, 0, 0, 0, 0]])  # (batch=1, T=10)

embedding = nn.Embedding(num_embeddings=10_000, embedding_dim=300, padding_idx=0)
x = embedding(src_ids)  # (1, 10, 300)

print(x.shape)  # one 300-dimensional input vector per time step

Step B: encoder RNN reads the English sentence

The encoder consumes one embedding at a time and updates hidden state. If a 10-step tensor is used for batching, the meaningful tokens occupy the early positions and the remaining positions are padding. In production code, lengths or masks prevent padding from contributing to the loss and, depending on implementation, from changing the final state.

Encoder step Input token Hidden-state interpretation
1myStarts the sentence and records a possessive cue.
2nameBuilds the phrase “my name” and the identity context.
3isAdds the grammatical relation that links phrase to value.
4dineshStores the name entity that should be copied or transliterated.
5<EOS>Marks that the source sentence is complete.
6-10<PAD>Ignored by masks/lengths; present only so the batch has a rectangular tensor shape.

Step C: decoder RNN generates French one token at a time

The decoder starts from the encoder’s final meaning representation. At each step it receives the previous French token and predicts a probability distribution over the French vocabulary. During training, it often receives the true previous token as input (teacher forcing). During inference, it feeds its own previous prediction back in.

Decoder step Decoder input Prediction Why it happens
1<SOS>monThe start token asks the decoder to begin the translation.
2monnomThe decoder continues the French phrase “mon nom”.
3nomestThe model emits the linking verb.
4estdineshThe name entity is carried through from the encoded source context.
5dinesh<EOS>The decoder decides the target sentence is complete.
6-10<PAD>ignoredPadding positions are ignored when batching fixed-length targets.
 
# Decoder inference sketch: generate French tokens autoregressively.
# This is conceptual pseudocode; real systems use batching, masks, beam search,
# and often attention over all encoder states.

prev_token = SOS_ID
hidden = encoder_final_hidden
generated = []

for _ in range(max_target_len):
    prev_emb = target_embedding(torch.tensor([[prev_token]]))  # (1, 1, D)
    decoder_out, hidden = decoder_rnn(prev_emb, hidden)
    logits = output_projection(decoder_out[:, -1, :])          # (1, vocab_size)
    next_token = int(logits.argmax(dim=-1).item())

    if next_token == EOS_ID:
        break

    generated.append(next_token)
    prev_token = next_token  # feed the model's own prediction back in
What actually learns: gradients flow through the unrolled encoder and decoder during training. The model adjusts embeddings, recurrent weights, and output-projection weights so that the right target token receives higher probability at each decoder step.

5) Pseudocode: forward pass through a sequence

# Given:
#   X: shape (T, D)
#   h0: shape (M,)   (often zeros)
#   weights: W_xh (M, D), W_hh (M, M), b_h (M,)
#            W_ho (O, M), b_o (O,)
# Returns:
#   y_hats: list of length T, each element shape (O,)

h = h0
y_hats = []
for t in range(T):
    h = tanh(W_xh @ X[t] + W_hh @ h + b_h)   # hidden update
    y = softmax(W_ho @ h + b_o)              # output (for classification)
    y_hats.append(y)

# For many-to-one tasks, you would use y_hats[-1] and ignore the rest.

6) Cost savings: RNN vs flattened ANN

Let:

  • \(T\) = sequence length
  • \(D\) = features per time step
  • \(M\) = hidden size
  • \(O\) = output size (e.g., \(O=1\) for binary classification/logit)

Flattened ANN (dense “everything-to-everything”)

If you flatten, input size is \(T\cdot D\). If you also keep a hidden representation for each time step (as in the transcript’s comparison), hidden size becomes \(T\cdot M\).

Approx weights (ignoring biases): \[ (T D)(T M) + (T M)O \]

RNN (shared weights through time)

Weights are independent of \(T\): \[ W_{xh}: M D,\quad W_{hh}: M^2,\quad W_{ho}: O M \] Total: \[ MD + M^2 + OM \]

This comparison is about trainable parameters. Runtime still scales with sequence length because the recurrent update is applied at every step. For many-to-one tasks, the output head may only be applied to the final hidden state; for many-to-many tasks, it is applied at each step, which changes compute but not the shared recurrent parameter count.

Key win: RNN parameter count does not grow with sequence length \(T\) the way a flattened dense model does.

Concrete example + Python code (and a plot)

Example: \(T=100\), \(D=10\), \(M=15\), \(O=1\). 

import numpy as np
import matplotlib.pyplot as plt

def ann_params_flat(T, D, M, O):
    # Transcript-style comparison: hidden size = T*M
    return (T*D) * (T*M) + (T*M) * O

def rnn_params(T, D, M, O):
    # Shared through time
    return (M*D) + (M*M) + (O*M)

T, D, M, O = 100, 10, 15, 1
p_ann = ann_params_flat(T, D, M, O)
p_rnn = rnn_params(T, D, M, O)

print("Flattened ANN params:", p_ann)
print("RNN params:", p_rnn)
print("ANN / RNN ratio:", p_ann / p_rnn)

# Quick bar plot
labels = ["Flattened ANN", "RNN (shared weights)"]
values = [p_ann, p_rnn]

plt.figure()
plt.bar(labels, values)
plt.yscale("log")  # so both bars are visible
plt.title("Parameter count comparison (log scale)")
plt.ylabel("Number of parameters")
plt.show()

In this setup, you’ll see a huge ratio (thousands of times more parameters for the flattened ANN), matching the intuition from the transcript.

7) Coding it in PyTorch: manual loop (to really see weight sharing)

The fastest way to “get” RNNs is to implement the loop yourself once. Below is a minimal RNN cell you can train like any other module. 

import torch
import torch.nn as nn
import torch.nn.functional as F

class TinyElmanRNN(nn.Module):
    """
    Vanilla RNN (Elman unit) implemented explicitly:
      h_t = tanh(W_xh x_t + W_hh h_{t-1} + b_h)
      y_t = W_ho h_t + b_o
    """
    def __init__(self, input_size: int, hidden_size: int, output_size: int):
        super().__init__()
        self.input_size = input_size
        self.hidden_size = hidden_size
        self.output_size = output_size

        # These are the ONLY learned weights, reused for every t
        self.W_xh = nn.Linear(input_size, hidden_size, bias=True)
        self.W_hh = nn.Linear(hidden_size, hidden_size, bias=False)
        self.W_ho = nn.Linear(hidden_size, output_size, bias=True)

    def forward(self, x: torch.Tensor, h0: torch.Tensor | None = None):
        """
        x: (batch, T, D)  using batch_first layout here
        h0: (batch, M) or None
        Returns:
          y_all: (batch, T, O)  (pred at every step)
          h_last: (batch, M)
        """
        B, T, D = x.shape
        if h0 is None:
            h = torch.zeros(B, self.hidden_size, device=x.device, dtype=x.dtype)
        else:
            h = h0

        y_steps = []
        for t in range(T):
            xt = x[:, t, :]  # (batch, D)
            h = torch.tanh(self.W_xh(xt) + self.W_hh(h))
            yt = self.W_ho(h)  # (batch, O)
            y_steps.append(yt)

        y_all = torch.stack(y_steps, dim=1)  # (batch, T, O)
        return y_all, h

# Example usage:
B, T, D = 32, 100, 10
M, O = 15, 1
model = TinyElmanRNN(D, M, O)

x = torch.randn(B, T, D)
y_all, h_last = model(x)

# Many-to-one binary classification: use only last step
logits = y_all[:, -1, :]         # (B, 1)
probs  = torch.sigmoid(logits)   # if binary classification
Notice how self.W_xh and self.W_hh are created once in __init__, then used repeatedly inside the time loop. That’s the “single unit reused” idea in code.

8) Using PyTorch’s built-in nn.RNN (recommended for real projects)

PyTorch provides torch.nn.RNN which handles the looping internally and exposes standardized weights (e.g., weight_ih_l0, weight_hh_l0) and batch/sequence layouts. 

import torch
import torch.nn as nn

D, M = 10, 15   # input_size, hidden_size
rnn = nn.RNN(
    input_size=D,
    hidden_size=M,
    num_layers=1,
    nonlinearity="tanh",
    batch_first=True,  # input is (batch, T, D)
)

B, T = 32, 100
x = torch.randn(B, T, D)

# output: (B, T, M)   h_n: (num_layers, B, M)
out, h_n = rnn(x)

# Many-to-one classifier head
head = nn.Linear(M, 1)
logits = head(out[:, -1, :])

If you’re ever unsure about shapes, inputs/outputs, or the exact meaning of those weight tensors, the official docs are the source of truth.

Why the next section exists: nn.RNN gives you a clean implementation of the vanilla recurrence, but it does not change the recurrence itself. There is still only one hidden vector, and every new token can overwrite it. That is enough for short dependencies and for learning the idea, but it is too blunt when the model must remember something for many steps while also reacting to new input.

9) Why vanilla RNN memory breaks: overwriting and gradient chains

A vanilla RNN has only one state vector \(h_t\). Every step computes a new state from the current input and the previous state:

\[ h_t = \tanh(W_{xh}x_t + W_{hh}h_{t-1} + b_h) \]

That compact formula is elegant, but it gives the model no explicit mechanism for deciding how much old information to keep and how much new information to write. The new candidate state can overwrite the old state too aggressively. During backpropagation through time, gradients also repeatedly multiply through recurrent transformations. Those products can shrink toward zero (vanishing gradients) or grow too large (exploding gradients).

The missing idea: a good sequence model needs a learnable way to say “keep this memory”, “forget this part”, “write this new information”, and sometimes “hide this internal memory from the output”.

10) Gates: learnable valves for memory

The next improvement is not “make the hidden state bigger” as the first move. A larger state can store more numbers, but it still gives the model no explicit instruction for which numbers should be preserved, overwritten, or exposed. GRUs and LSTMs solve that problem by adding gates. A gate is usually a sigmoid output:

\[ \sigma(a) \in (0,1) \]

Because a gate is between 0 and 1, it behaves like a soft valve:

  • A value near 0 means “block this signal”.
  • A value near 1 means “let this signal pass”.
  • Intermediate values blend old and new information.

The progression is:

Model Problem it fixes Remaining pressure that leads to the next idea
Vanilla RNN Introduces hidden state and weight sharing through time. The hidden state is overwritten by a single update rule, and long gradients are fragile.
GRU Adds reset/update gates so the model can keep old state or write new state selectively. There is still one vector doing two jobs: long-term memory and exposed hidden representation.
LSTM Separates protected cell memory \(c_t\) from exposed hidden state \(h_t\). The computation is still sequential, and seq2seq still pressures memory into recurrent states.
Attention Lets the decoder look up relevant states directly instead of relying only on what survived in memory. The Transformer generalizes lookup so all tokens can read context directly and train in parallel.

Historical note: LSTM was introduced before GRU. This chapter teaches GRU first because it is the simpler gated cell to understand, then LSTM as the more explicit long-term-memory design.

11) GRU: the simpler gated memory cell

A Gated Recurrent Unit is the smallest useful step beyond the vanilla RNN. It keeps one state, \(h_t\), like a vanilla RNN, but adds two gates:

  • Reset gate \(r_t\): controls how much of the previous state is used when computing the new candidate.
  • Update gate \(z_t\): controls how much old state is kept versus how much candidate state is written.

One common convention, matching PyTorch’s documentation, is:

\[ r_t = \sigma(W_{ir}x_t + b_{ir} + W_{hr}h_{t-1} + b_{hr}) \] \[ z_t = \sigma(W_{iz}x_t + b_{iz} + W_{hz}h_{t-1} + b_{hz}) \] \[ n_t = \tanh(W_{in}x_t + b_{in} + r_t \odot (W_{hn}h_{t-1} + b_{hn})) \] \[ h_t = (1 - z_t) \odot n_t + z_t \odot h_{t-1} \]

With this convention, if \(z_t\) is close to 1, the GRU mostly keeps the old state. If \(z_t\) is close to 0, it mostly writes the candidate \(n_t\). That “keep vs update” interpolation is the key mental model.

GRU mental model: “I have one memory vector. At each step I learn whether to keep it, partially reset it, or overwrite parts of it with the new candidate.”

This directly addresses the first failure mode of a vanilla RNN: accidental overwrite. If the model sees an important token early in a sequence, the update gate can keep that memory alive while less important later tokens only adjust part of the state. The reset gate gives the model a second useful behavior: when the current input starts a new local pattern, it can temporarily ignore older state while computing the candidate update. 

import torch
import torch.nn as nn

B, T, D = 32, 100, 10     # batch, sequence length, input features
H = 64                    # hidden size

gru = nn.GRU(
    input_size=D,
    hidden_size=H,
    num_layers=1,
    batch_first=True,
)

x = torch.randn(B, T, D)
out, h_n = gru(x)

print(out.shape)  # (B, T, H): hidden state at every time step
print(h_n.shape)  # (1, B, H): final hidden state for the last layer

# Many-to-one classifier: use the final time-step representation
head = nn.Linear(H, 1)
logits = head(out[:, -1, :])
Why move from GRU to LSTM? A GRU is compact and often very strong, but its single state vector still has to be both the long-term memory and the visible representation passed onward. If you want a more explicit design where long-term memory can be preserved while only part of it is exposed at the current step, you need a separate memory path. That is the reason for the LSTM cell state.

12) LSTM: separate long-term memory from exposed hidden state

A Long Short-Term Memory cell takes the gating idea further by adding a separate cell state, \(c_t\), alongside the hidden state, \(h_t\). The cell state is the long-term memory path. The hidden state is the exposed representation used for outputs and for the next recurrent computation.

LSTMs use three main gates plus a candidate update:

  • Forget gate \(f_t\): how much old cell memory \(c_{t-1}\) to keep.
  • Input/write gate \(i_t\): how much new candidate information to write.
  • Candidate \(g_t\): proposed new content for the cell memory.
  • Output gate \(o_t\): how much cell memory to expose as hidden state \(h_t\).
\[ f_t = \sigma(W_{if}x_t + b_{if} + W_{hf}h_{t-1} + b_{hf}) \] \[ i_t = \sigma(W_{ii}x_t + b_{ii} + W_{hi}h_{t-1} + b_{hi}) \] \[ g_t = \tanh(W_{ig}x_t + b_{ig} + W_{hg}h_{t-1} + b_{hg}) \] \[ o_t = \sigma(W_{io}x_t + b_{io} + W_{ho}h_{t-1} + b_{ho}) \] \[ c_t = f_t \odot c_{t-1} + i_t \odot g_t \] \[ h_t = o_t \odot \tanh(c_t) \]
LSTM mental model: “I keep a protected long-term notebook \(c_t\), decide what to erase, decide what to write, and decide how much of the notebook to show as \(h_t\).” 
import torch
import torch.nn as nn

B, T, D = 32, 100, 10
H = 64

lstm = nn.LSTM(
    input_size=D,
    hidden_size=H,
    num_layers=1,
    batch_first=True,
)

x = torch.randn(B, T, D)
out, (h_n, c_n) = lstm(x)

print(out.shape)  # (B, T, H): hidden state at every time step
print(h_n.shape)  # (1, B, H): final hidden state
print(c_n.shape)  # (1, B, H): final cell state

head = nn.Linear(H, 1)
logits = head(out[:, -1, :])

Compared with a GRU, the LSTM is more explicit: one gate forgets old cell memory, one gate writes new cell memory, and one gate controls what part of the internal memory becomes visible as \(h_t\). That makes the design easier to reason about for long dependencies, but it also adds parameters and computation. In practice, GRU is often a good first gated baseline; LSTM is the stronger choice when you want the separate cell-memory path and can afford the extra complexity.

Why LSTM still does not finish the story: LSTMs make recurrence better, but they are still recurrent. Step \(t\) still waits for step \(t-1\), and an encoder-decoder LSTM still tends to compress source information into recurrent states. The next idea is not another gate; it is a different memory interface: direct lookup over earlier token states.

13) GRU vs LSTM vs vanilla RNN: when to use which

The choice is therefore not a popularity contest. It follows the problem you are trying to solve. Use the simplest recurrent cell that carries enough memory for the task, then move to the next mechanism only when the limitation becomes the bottleneck.

Cell State carried through time Memory control Practical use
Vanilla RNN One hidden state \(h_t\) No explicit gates Best for teaching and very short dependencies; rarely the strongest production choice.
GRU One hidden state \(h_t\) Reset and update gates Simpler than LSTM, fewer parameters, often a strong baseline for sequence classification/forecasting.
LSTM Hidden state \(h_t\) plus cell state \(c_t\) Forget, input/write, candidate, output gates More explicit memory control; useful when long dependencies matter and recurrence is still appropriate.
Attention/Transformer Token representations plus attention over context Content-based lookup instead of recurrent compression Dominant for LLMs because training parallelizes and each token can directly access relevant context.

Bidirectional recurrent models

After gates, another natural question is direction: if the entire input sentence is already known, why should the model only read left-to-right? A bidirectional RNN/GRU/LSTM runs one recurrent model left-to-right and another right-to-left, then combines their representations. This is useful when the full input sequence is known, such as classification, tagging, or embedding a sentence. It is not valid for pure left-to-right generation, because a generator cannot use future tokens that have not been produced yet. 

import torch
import torch.nn as nn

B, T, D = 32, 100, 10
H = 64

encoder = nn.LSTM(
    input_size=D,
    hidden_size=H,
    batch_first=True,
    bidirectional=True,
)

x = torch.randn(B, T, D)
out, (h_n, c_n) = encoder(x)

print(out.shape)  # (B, T, 2*H): forward and backward states concatenated

14) Why attention still mattered after GRU/LSTM

At this point the story has fixed three problems: weight sharing made sequence models compact, gates made memory controllable, and bidirectionality let encoders use both left and right context when the full input is known. But none of these changes remove the deepest recurrent limitation:

  • Sequential compute: step \(t\) depends on \(t-1\), so training cannot parallelize across time as easily as Transformers.
  • Compression pressure: encoder-decoder recurrence still tends to squeeze a whole source sequence through hidden states.
  • Long-context access: a decoder may need a specific old token directly, not just whatever survived in state.

Attention keeps the useful idea of sequence-conditioned output, but changes the memory interface. Instead of asking one hidden state to carry everything, the decoder can look back at all encoder states. The Transformer then takes the next step: it uses self-attention so tokens can read other tokens directly.

Bridge to Transformers: GRU/LSTM make recurrent memory more controllable. Attention changes the shape of memory itself from “carry a state forward” to “look up the relevant token states when needed.”

15) Quick mental model recap

  • RNN = MLP cell + memory. The “memory” is the hidden state \(h_t\).
  • One cell reused at every time step. Same weights, new data + updated state.
  • GRU = RNN + keep/reset gates. It has one hidden state but learns how much old state to preserve.
  • LSTM = RNN + protected cell state. It separates long-term cell memory \(c_t\) from exposed hidden state \(h_t\).
  • Outputs at every step are optional. Many tasks use only the last output; translation uses stepwise decoder outputs.
  • Cost savings come from sharing. Parameter count doesn’t blow up with \(T\).
  • Padding is not meaning. Padding makes rectangular tensors; masks/lengths stop it from affecting learning.
  • Encoder-decoder RNNs are historical but important. They explain the vocabulary of hidden state, teacher forcing, autoregressive decoding, and attention.
